## Java 12

JDK 12 được phát hành vào ngày 19 tháng 3 năm 2019, đây là một phiên bản không phải LTS.

Bài viết này chọn giới thiệu chi tiết một số tính năng mới quan trọng:

- [JEP 189: Shenandoah: A Low-Pause-Time Garbage Collector (Experimental)](https://openjdk.org/jeps/189)
- [JEP 325: Switch Expressions (Preview) (biểu thức switch, tính năng preview)](https://openjdk.org/jeps/325)
- [JEP 334: JVM Constants API (JVM Constants API)](https://openjdk.org/jeps/334)
- [JEP 344: Abortable Mixed Collections for G1 (mixed collection có thể hủy của G1)](https://openjdk.org/jeps/344)
- [JEP 346: Promptly Return Unused Committed Memory (trả về kịp thời committed memory chưa sử dụng của G1)](https://openjdk.org/jeps/346)

Hình dưới đây thể hiện số lượng tính năng mới và thời điểm cập nhật của mỗi phiên bản từ JDK 8 đến JDK 25:

![Số lượng tính năng mới và thời điểm cập nhật của mỗi phiên bản từ JDK 8 đến JDK 25](https://oss.javaguide.cn/github/javaguide/java/new-features/jdk8~jdk24.png)

### JEP 189: Shenandoah (low-latency garbage collector, experimental)

Shenandoah là garbage collector có thời gian pause thấp do Red Hat chủ trì phát triển, mục tiêu là duy trì thời gian pause ngắn nhất có thể và tương đối độc lập với kích thước heap khi heap lớn.

So với ZGC được open source trong Java 11 (cần nâng cấp lên JDK 11 mới có thể sử dụng), Shenandoah có phiên bản JDK8u ổn định. Trong bối cảnh Java 8 đang chiếm thị phần chính, Shenandoah có tính khả thi thực tế cao hơn.

### JEP 344 & JEP 346: Tối ưu G1 collector

Java 12 mang đến hai cập nhật cho garbage collector mặc định G1:

- **Mixed collection có thể hủy**: JEP 344 tách tập region cần được thu hồi (mixed collection set) thành phần bắt buộc và phần tùy chọn để đạt mục tiêu thời gian pause do người dùng cung cấp, nhờ đó G1 garbage collector có thể hủy quá trình garbage collection. G1 có thể hủy việc thu hồi phần tùy chọn để đạt mục tiêu thời gian pause.
- **Trả về kịp thời committed memory chưa sử dụng**: JEP 346 cải thiện G1 GC để tự động trả Java heap memory về cho operating system khi rảnh.

### JEP 334: JVM Constants API (JVM Constants API)

JEP này giới thiệu một API để mô hình hóa các mô tả danh nghĩa của các class file và runtime artifact quan trọng, đặc biệt là các constant có thể được load từ constant pool.

API này cung cấp một nhóm interface và utility class để biểu diễn và thao tác với các constant pool entry trong class file. Các thành phần chính gồm:

- **Constant descriptor interface**: interface `ConstantDesc` và các subinterface của nó, dùng để mô tả nhiều loại constant.
- **Constant value type**: `ClassDesc`, `MethodTypeDesc`, `MethodHandleDesc`, `DynamicConstantDesc`, v.v.
- **Bootstrap method**: hỗ trợ instruction `invokedynamic` và bootstrap method cho dynamic constant.

API này chủ yếu hỗ trợ các trường hợp sau:

1. **Thao tác class file**: cung cấp cách chuẩn hóa để mô tả và thao tác với constant pool trong class file.
2. **Sinh bytecode**: đơn giản hóa tương tác giữa các framework sinh bytecode (như ASM) và code Java.
3. **Cải tiến reflection**: giúp các thao tác reflection an toàn kiểu hơn và giàu khả năng biểu đạt hơn.
4. **Công cụ compiler**: cung cấp abstraction tốt hơn cho compiler và công cụ sinh code.

API này là một cải tiến tầng dưới quan trọng trong Java 12, đặt nền tảng cho các tính năng thao tác bytecode và compiler về sau.

### JEP 325: Switch Expressions (switch expression, preview)

Cú pháp `switch` truyền thống dễ gặp vấn đề quên viết `break`; xét về độ gọn gàng của code, nhiều `break` về bản chất cũng là một dạng lặp lại.

Java 12 cải tiến `switch` expression, sử dụng execution block sau khi điều kiện match thành công với cú pháp tương tự lambda, không cần viết thêm `break`.

```java
switch (day) {
    case MONDAY, FRIDAY, SUNDAY -> System.out.println(6);
    case TUESDAY                -> System.out.println(7);
    case THURSDAY, SATURDAY     -> System.out.println(8);
    case WEDNESDAY              -> System.out.println(9);
}
```

## Java 13

JDK 13 được phát hành vào ngày 17 tháng 9 năm 2019, đây là một phiên bản không phải LTS.

Bài viết này chọn giới thiệu chi tiết một số tính năng mới quan trọng:

- [JEP 350: Dynamic CDS Archives (dynamic CDS archive)](https://openjdk.org/jeps/350)
- [JEP 351: ZGC: Uncommit Unused Memory (ZGC giải phóng memory chưa sử dụng)](https://openjdk.org/jeps/351)
- [JEP 355: Text Blocks (Preview) (text block, tính năng preview)](https://openjdk.org/jeps/355)
- [JEP 354: Switch Expressions (Second Preview) (switch expression, preview lần thứ hai)](https://openjdk.org/jeps/354)

Hình dưới đây thể hiện số lượng tính năng mới và thời điểm cập nhật của mỗi phiên bản từ JDK 8 đến JDK 24:

![](https://oss.javaguide.cn/github/javaguide/java/new-features/jdk8~jdk24.png)

### JEP 351: ZGC (giải phóng memory chưa sử dụng)

ZGC được đưa vào Java 11 dưới dạng experimental gặp vấn đề trong thực tế sử dụng: không chủ động giải phóng memory chưa sử dụng về cho operating system.

ZGC heap gồm một nhóm heap region có tên là ZPages. Trong GC cycle, khi các region ZPages được làm trống, chúng sẽ được giải phóng và trả về page cache **ZPageCache**; các ZPages trong cache này được tổ chức theo thứ tự ít được sử dụng gần đây nhất (LRU) và theo kích thước.

Trong Java 13, ZGC sẽ trả về operating system các page được xác định là đã lâu không sử dụng, để chúng có thể được process khác tái sử dụng.

### JEP 350: Dynamic CDS Archives (dynamic CDS archive)

Java 13 tiếp tục đơn giản hóa, cải tiến và mở rộng Application Class Data Sharing (AppCDS) được giới thiệu trong Java 10, cụ thể là: **cho phép archive class một cách động khi ứng dụng Java kết thúc thực thi**. Các class có thể được archive bao gồm mọi application class và class trong referenced library đã được load nhưng không thuộc default base CDS.

Điều này nâng cao khả năng sử dụng của Application Class Data Sharing ([AppCDS](https://openjdk.java.net/jeps/310)). Người dùng không cần chạy thử để tạo class list cho từng ứng dụng.

```bash
java -XX:ArchiveClassesAtExit=my_app_cds.jsa -cp my_app.jar
java -XX:SharedArchiveFile=my_app_cds.jsa -cp my_app.jar
```

### JEP 355: Text Blocks (text block, preview)

Để giải quyết vấn đề Java chỉ có thể hỗ trợ chuỗi nhiều dòng bằng cách escape newline hoặc dùng toán tử nối dòng, Java 13 giới thiệu **ba dấu ngoặc kép liên tiếp** để định nghĩa văn bản nhiều dòng.

Java 13 hỗ trợ diễn giải mọi nội dung nằm giữa hai ký hiệu `"""` thành một phần của string, bao gồm cả newline. Lưu ý: “hai” ở đây nên được hiểu là “một cặp”, tức là một ký hiệu ở đầu và một ký hiệu ở cuối.

Cách viết HTML trước khi hỗ trợ text block:

```java
String json ="{\n" +
              "   \"name\":\"mkyong\",\n" +
              "   \"age\":38\n" +
              "}\n";
```

Cách viết HTML sau khi hỗ trợ text block:

```java
 String json = """
                {
                    "name":"mkyong",
                    "age":38
                }
                """;
```

Cách viết SQL trước khi hỗ trợ text block:

```sql
String query = "SELECT `EMP_ID`, `LAST_NAME` FROM `EMPLOYEE_TB`\n" +
               "WHERE `CITY` = 'INDIANAPOLIS'\n" +
               "ORDER BY `EMP_ID`, `LAST_NAME`;\n";
```

Cách viết SQL sau khi hỗ trợ text block:

```sql
String query = """
               SELECT `EMP_ID`, `LAST_NAME` FROM `EMPLOYEE_TB`
               WHERE `CITY` = 'INDIANAPOLIS'
               ORDER BY `EMP_ID`, `LAST_NAME`;
               """;
```

Giới thiệu các method liên quan đến text block (`formatted()`, `stripIndent()`, `translateEscapes()`), xem phần [API enhancement - String enhancement (method liên quan đến text block)](#string-增强文本块相关方法) trong bài viết này.

### JEP 354: Switch Expressions (switch expression, preview lần thứ hai)

Trong `Switch` expression có thêm một keyword dùng để thoát khỏi block `Switch`, đó là `yield`, chủ yếu dùng để trả về một value.

Điểm khác nhau giữa `yield` và `return`: `return` kết thúc method hiện tại và trả về kết quả, còn `yield` kết thúc branch của `switch` expression hiện tại và tạo ra value của expression đó. `switch` expression phải bao phủ mọi input có thể xảy ra, nhưng khi đã liệt kê hết mọi giá trị thì không nhất thiết cần branch `default`.

```java
 private static String descLanguage(String name) {
        return switch (name) {
            case "Java": yield "object-oriented, platform independent and secured";
            case "Ruby": yield "a programmer's best friend";
            default: yield name +" is a good language";
        };
 }
```

## Cải tiến API

Không phải mọi thay đổi API đều được phát hành thông qua JEP (Java Enhancement Proposal).

Trong quy trình phát triển JDK: **JEP** thường dùng cho các thay đổi lớn, chẳng hạn như giới thiệu language feature mới (như `switch` expression), cơ chế JVM mới (như ZGC) hoặc refactor library quy mô lớn. Những thay đổi như thêm vài method vào class hiện có, chẳng hạn `String.indent()`, thường được xem là bảo trì library thông thường. Chúng được developer JDK trực tiếp submit và review thông qua ticket của **JBS (JDK Bug System)**, sau đó được phát hành theo phiên bản.

### Cải tiến String

Java 12 bổ sung hai method xử lý string.

#### indent() - method thụt lề

Method `indent()` có thể dùng để thụt lề string.

```java
String text = "Java";
// Thụt lề 4 khoảng trắng
text = text.indent(4);
System.out.println(text);
text = text.indent(-10);
System.out.println(text);
```

Output:

```plain
     Java
Java
```

#### transform() - method chuyển đổi

Method `transform()` có thể dùng để chuyển đổi string được chỉ định.

```java
String result = "foo".transform(input -> input + " bar");
System.out.println(result); // foo bar
```

### Cải tiến Files

Java 12 thêm method `mismatch()` để so sánh hai file:

```java
public static long mismatch(Path path, Path path2) throws IOException
```

Method `mismatch()` dùng để so sánh hai file và trả về vị trí byte đầu tiên không khớp; nếu hai file giống nhau thì trả về `-1L`.

Ví dụ code (trường hợp nội dung hai file giống nhau):

```java
Path filePath1 = Files.createTempFile("file1", ".txt");
Path filePath2 = Files.createTempFile("file2", ".txt");
Files.writeString(filePath1, "Java 12 Article");
Files.writeString(filePath2, "Java 12 Article");

long mismatch = Files.mismatch(filePath1, filePath2);
assertEquals(-1, mismatch);
```

Ví dụ code (trường hợp nội dung hai file khác nhau):

```java
Path filePath3 = Files.createTempFile("file3", ".txt");
Path filePath4 = Files.createTempFile("file4", ".txt");
Files.writeString(filePath3, "Java 12 Article");
Files.writeString(filePath4, "Java 12 Tutorial");

long mismatch = Files.mismatch(filePath3, filePath4);
assertEquals(8, mismatch);
```

### Cải tiến NumberFormat

Trong Java 12, `NumberFormat` bổ sung hỗ trợ format các số phức tạp:

```java
NumberFormat fmt = NumberFormat.getCompactNumberInstance(Locale.US, NumberFormat.Style.SHORT);
String result = fmt.format(1000);
System.out.println(result);
```

Output:

```plain
1K
```

### Cải tiến Socket API

Java 13 viết lại tầng dưới của Socket API. `NioSocketImpl` là phần thay thế trực tiếp cho `PlainSocketImpl`; nó sử dụng lock trong package `java.util.concurrent` thay vì synchronized method. Nếu muốn sử dụng implementation cũ, hãy dùng `-Djdk.net.usePlainSocketImpl=true`.

Ngoài ra, Java 13 mặc định sử dụng Socket implementation mới.

```java
public final class NioSocketImpl extends SocketImpl implements PlatformSocketImpl {
}
```

### Cải tiến FileSystems

Trong Java 13, class `FileSystems` thêm ba method mới dưới đây, giúp sử dụng dễ hơn các file system provider coi nội dung file như một file system:

- `newFileSystem(Path)`
- `newFileSystem(Path, Map<String, ?>)`
- `newFileSystem(Path, Map<String, ?>, ClassLoader)`

### Cải tiến String (method liên quan đến text block)

Java 13 giới thiệu text block dưới dạng preview feature, class `String` bổ sung 3 method mới để thao tác với text block:

- `formatted(Object... args)`: tương tự method `format()` của `String`. Method này được thêm để hỗ trợ format text block.
- `stripIndent()`: dùng để loại bỏ khoảng trắng ở đầu và cuối mỗi dòng trong text block.
- `translateEscapes()`: chuyển escape sequence như _"\\\t"_ thành _"\t"_.

Vì text block là một preview feature và có thể bị xóa trong các phiên bản tương lai, các method mới này được đánh dấu là deprecated.

```java
@Deprecated(forRemoval=true, since="13")
public String stripIndent() {
}
@Deprecated(forRemoval=true, since="13")
public String formatted(Object... args) {

}
@Deprecated(forRemoval=true, since="13")
public String translateEscapes() {
}
```

Để xem giới thiệu chi tiết về text block, hãy xem phần [JEP 355: Text Blocks (Preview)](#jep-355-text-blocks-preview) trong bài viết này.

## Bổ sung

### Về preview feature

Trước tiên, hãy trích nguyên văn từ website Oracle: `This is a preview feature, which is a feature whose design, specification, and implementation are complete, but is not permanent, which means that the feature may exist in a different form or not at all in future JDK releases. To compile and run code that contains preview features, you must specify additional command-line options.`

Đây là một preview feature có thiết kế, đặc tả và implementation hoàn chỉnh nhưng không mang tính vĩnh viễn. Điều đó có nghĩa là feature này có thể tồn tại dưới hình thức khác hoặc hoàn toàn không tồn tại trong các bản phát hành JDK tương lai. Để compile và run code chứa preview feature, phải chỉ định thêm các command-line option.

Lấy `switch` expression làm ví dụ: feature này bắt đầu preview từ Java 12, tiếp tục được điều chỉnh trong Java 13 và trở thành language feature chính thức trong Java 14. Sau khi chính thức hóa, syntax và semantics của nó trở thành một phần của Java SE specification, không còn cần bật preview feature.

Một mặt, có thể thấy JDK, với tư cách là platform tiêu chuẩn, rất thận trọng khi bổ sung feature mới. Mặt khác, theo quan điểm cá nhân, nên thận trọng khi sử dụng preview feature. Thiết kế và implementation của feature có thể dễ dàng, nhưng giá trị thực tế vẫn cần được kiểm chứng trong quá trình sử dụng.

### Tối ưu JVM

Mỗi lần phát hành phiên bản Java đều đi kèm tối ưu cho JVM, bao gồm cải tiến garbage collection algorithm hiện có, giới thiệu garbage collection algorithm mới và loại bỏ các garbage collection algorithm cũ không còn phù hợp với hiện tại.

Hướng tối ưu tổng thể là **garbage collection hiệu quả, độ trễ thấp**.

Developer phát triển ứng dụng hằng ngày có thể quan tâm hơn đến syntax feature mới, nhưng từ góc độ doanh nghiệp, khi cân nhắc có nên nâng cấp Java platform hay không, điều được quan tâm hơn là **cải thiện runtime của JVM**.
